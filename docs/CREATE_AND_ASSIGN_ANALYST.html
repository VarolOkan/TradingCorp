Creating a New Analyst & Assigning It to an Agency

A practical, illustrated walkthrough of the Settings dialog in the Financial Analysis Pipeline. This guide is grounded in the actual UI code (frontend/src/components/SettingsDialog.tsx and the analyst/agency dialogs), so every label, button, and endpoint named here is real.

Assumption: by “assign it to” you mean assign the new analyst to an Agency (a flow). That is the most common case, and it is covered in full below. The same analyst can also be wired into a flow via the re-org dialog — see Section 5.

Two separate actions. “Create the analyst” and “assign it to an agency” are different sub-flows in two different tabs. You create the analyst in the Analysts tab, then assign it in the Agencies tab (or the agency re-org dialog). Creating the analyst alone does not put it into any flow.

1. The big picture

The pipeline is a graph of analysts grouped into agencies. Each agency is an ordered list of analysts (the “wall”). A custom analyst you create is just a registry entry until you tick it inside an agency — only then does it run as part of that agency’s analysis.

Figure 1 — A custom analyst (✦) is created in the catalog, then ticked into an agency’s ordered flow.

2. Create a new analyst (Analysts tab)

Open Settings (gear icon) → click the Analysts tab. Built-in analysts are read-only. The bottom form (“New analyst”) is where you create your own.

  1. Fill the core fields. Only Id and Name are required.
    • Id — snake_case, unique, e.g. my_credit_analyst. Lowercase + underscores. Disabled once you edit an existing one.
    • Name — display name shown on the wall, e.g. My Credit Analyst.
    • Role — a short one-line summary (optional, cosmetic).
  2. Pick its shape.
    • Kind — orchestrator / ingestion / analyst / gatekeeper.
    • Stage — 1 · intake, 2 · analysis, or 3 · decision. Stage sets where the card sits in the flow order.
    • Accent — card color on the wall.
    • Depends on — comma-separated analyst ids this one waits for, e.g. data_ingestion, fundamental.
  3. Define its data (optional but recommended).
    • Input data (dataSources) — click + Add input source; each row has id, label, from, fields (csv), sources (csv).
    • Output data (output) — Channels, Verdict field, Score field, and the Store output in messages checkbox.
  4. Click Create analyst (bottom-right of the form). The UI POSTs to POST /registry/analyst, reloads the catalog, and the new row appears tagged custom. It now exists — but is not yet in any agency.

Figure 2 — Creating the analyst registers it as custom; it is not assigned to any agency yet.

Why a custom analyst ships a “no-op” logic. The backend requires every analyst definition to carry a logic block. A custom analyst created here is a registry entry, not a live handler, so the form sends logic: { mode: 'declarative', weighting: [] } to satisfy validation. It will only actually run once it is wired into an agency that reaches it in the flow.

3. Assign it to an agency (Agencies tab — the main way)

Still in Settings, click the Agencies tab. You can either create a brand-new agency that includes your analyst, or edit an existing one and tick your analyst on.

3a. Add the analyst to an existing agency

  1. Click the agency row in the list (e.g. Long-Term Investment). It loads into the “Edit agency” form.
  2. In the Analysts checklist, tick the box next to My Credit Analyst (your new custom analyst). The list is the full catalog, so your new analyst is there.
  3. Click Save changes. The UI PUTs the updated membership to PUT /registry/agency/:id, then refreshes the dropdown/wall immediately — no re-run needed.

3b. Create a new agency that includes the analyst

  1. With the form empty (click Cancel edit if an agency is loaded), set Id (e.g. credit-desk) and Name.
  2. Pick a Horizon: LONG_TERM / MEDIUM_TERM / INTRADAY. This drives the default screen interval (intraday → 5m, others → 1d).
  3. In the Analysts checklist, tick your new analyst and the others it should run with (at least one analyst is required; start from orchestrator, data_ingestion if unsure).
  4. Click Create agency → POST /registry/agency. It appears in the list and the agency selector dropdown right away.

Figure 3 — Ticking the analyst in the Agencies tab and saving wires it into the agency’s flow.

4. Alternative: the agency re-org dialog

From the main UI (not Settings), the agency selector has a [re-org] button (AgencySettingsDialog → AgencyReorgDialog). This lets you add, remove, and re-order analysts in an agency’s flow and set “feeds into” wiring (which later analysts depend on the re-orged one). It saves via PUT /registry/agency/:id and re-renders the wall live.

Use re-org when you care about order and dependencies (e.g. place your analyst between intake and decision, and wire feeds into: risk). Use the Agencies tab when you just want to toggle membership. Both hit the same backend endpoint; they are two front doors to the same data.

5. Verify it worked (no re-run needed)

  • In Settings → Agencies, the agency’s row now shows one more analyst in its N analysts count.
  • The main agency selector dropdown lists the agency (if new) immediately.
  • Selecting that agency renders the analyst wall with your custom card (in its stage / accent color) — this happens live via applyRegistryAgencies(); you do not have to wait for a “next run.”
  • To actually execute it, run an analysis for that agency. The custom analyst only performs work if the flow reaches it; with the no-op declarative logic it acts as a registry placeholder unless you later give it real behavior.

7. Common pitfalls

Analyst created but never runs

You created it but didn’t tick it in any agency (Section 3) or re-org (Section 4). A catalog entry alone is not a flow member.

Save button disabled

Agency save needs ≥1 analyst ticked and a non-empty Id. Analyst save needs both Id and Name.

Built-in analyst greyed out

Built-ins can’t be edited or deleted — only your custom ones can. Click a custom row to load it for edit.

Default agency can’t be deleted

The long-term default agency’s Delete is disabled by design. Create a new agency instead.
